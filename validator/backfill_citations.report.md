## Methodology

For each `(paper, tool)` pair the script searches the paper's `title`, `tldr`, `notes`, and `abstract` (plus `keywords` / `relevance_tags`) for one of:

1. **`url` (conf 1.0)** — literal `repository_url` substring.
2. **`slug` (conf 1.0)** — `owner/repo` GitHub slug as a standalone token.
3. **`name` (conf 0.9)** — tool `name` as a non-word-bounded phrase. Borderline single-word names (['agenta', 'agno', 'aider', 'cline', 'cody', 'continue-dev']…) require a corroborating context word in the surrounding 60-char window.
4. **`name+context` (conf 0.9)** — proprietary / academic products (['braintrust', 'claude-code', 'cursor', 'devin', 'github-copilot', 'langsmith']…) require both the name and a code-related context word in the surrounding window. Single-word brands that overlap with English nouns (['cursor', 'modal', 'v0', 'windsurf']) additionally require exact-case matching.

`cited_in` is the only field this script ever writes; an absent `cited_in` is created only when at least one paper id is being added. Existing entries are preserved in their original order, and new entries are appended sorted to keep runs idempotent.
